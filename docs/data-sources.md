# 数据来源

快照中的每个值都通过声明（Claim）指向一条来源登记（Source）。本文说明用了哪些来源、各自取什么、口径与时间，以及来源 ID 的编号规则。取数与溯源的实现见 [`architecture.md`](architecture.md)。

## 1. 时间口径

| 项目 | 日期 |
|---|---|
| 快照日（股价） | 2026-10-28 |
| 财务数据截至 | 最近一期申报的资产负债表日：127 家为 2026-06-30，其余 6 家因财年不同为 2026-03-31 至 2026-09-30 |
| 复核引用文档截止 | 2026-10-29（复核于 10-30 进行；其中 9 份是 10-29 发布的第三季度 10-Q、财报新闻稿等） |
| 快照生成 | 2026-11-01 |

财务数值（现金、债务、经营现金流）一律按上表资产负债表日取，不用第三季度报告更新；资产负债表日之后发生的增发、借款与可转换票据发行不计入企业价值，写在复核研究说明中，并列入 [`limitations-roadmap.md`](limitations-roadmap.md)。10-29 的文件用于临床结果、下一事件与资产权益等判断。

## 2. 来源清单

| 来源 | 取什么 | 接口 / 位置 | 来源 ID 形式 | 快照中条数 |
|---|---|---|---|---|
| ClinicalTrials.gov API v2 | 试验状态、阶段、设计、入组目标与实际、预计主要完成日、干预与适应症、已发布结果（主要终点） | `clinicaltrials.gov/api/v2/studies` | `CTG-<NCT 编号>` | 3,205 |
| SEC EDGAR XBRL | 现金及投资、债务、经营现金流、流通股 | `data.sec.gov/api/xbrl/companyfacts`（按标签优先级取值，裁剪后缓存，完整响应记哈希） | `SEC-<申报编号>` | 159 |
| SEC EDGAR 申报文件 | 10-K / 10-Q 正文（资产权益、合作协议、债务）、8-K 附件新闻稿 | `data.sec.gov/submissions` 定位，`sec.gov/Archives` 取文 | `SEC-<申报编号>` 或 `MAN-<股票代码>-<序号>` | 80 |
| openFDA | 已获批产品与申请号（NDA / BLA）、说明书适应症 | `api.fda.gov/download.json`（drugsfda 全量导出）、`api.fda.gov/drug/label.json` | `FDA-<申请号>`、`FDA-LABEL-<申请号>` | 105（另有 FDA 说明书与网页 61） |
| Nasdaq 行情 | 快照日收盘价（计算市值） | `api.nasdaq.com/api/quote/<代码>/historical` | `NASDAQ-<代码>-<日期>` | 133 |
| 公司新闻稿、投资者材料 | 临床结果、读出与申报时间、合作与权益 | 多为 SEC 8-K 附件；少量公司官网 | `MAN-<股票代码>-<序号>` | 92 |
| 论文与学会摘要 | 临床结果 | PubMed（NCBI E-utilities 官方接口） | `MAN-<股票代码>-<序号>` | 11 |
| 收购溢价样本 | 2025-01 至 2026-10 大药企现金收购美国上市生物科技公司的溢价 | SEC 原文（买方或标的的 8-K 等） | `MAN-PREM-<被收购方代码>` | 18 |
| 对方材料 | 10 家买方的画像、偏好、财务、专利到期；原有来源登记 | `docs/assignment/` 两份 Excel | 保留原编号（如 `PFE-3`、`ABBV-1`） | 44 |

每条来源登记记录：类型、标题、发布者、网址、发布日期、抓取时间；文档类另记本地存档路径（`data/raw/docs/`）与原文 SHA-256。

股价不是官方来源：SEC 不提供股价，公开行情中 Nasdaq 接口可脚本访问且带日期。市值 = 快照日收盘价 × SEC 申报的流通股；与 Nasdaq 自报市值逐家对比，120/131 家偏差在 10% 以内，余下差异来自股数日期口径。

## 3. 来源 ID 的编号规则

来源 ID 是本项目内部的编号，沿用对方材料「来源登记」表的格式（「主体-序号」），外界不使用。

- `CTG-`、`SEC-`、`FDA-` 后半段是官方编号（NCT 编号、SEC 申报编号、FDA 申请号），可以直接到官方网站查到原文。
- `MAN-` 表示人工登记的来源（manual）：复核时找到的新闻稿、申报附件、论文等没有统一官方编号的文件，登记在 `data/manual/sources.csv`。
- `DOC-<股票代码>-<哈希>`：LLM 抽取所用的存档文档（5 家深度研究公司），哈希取自原文内容。
- 对方材料的来源 ID 原样保留，便于与对方《来源登记》表对照；对方两份工作簿本身登记为 `MNC-WB`、`SPSIBI-WB`；Stage 0 排除名单另有 `PR-ANGELINI-CPRX`（收购完成公告）。

页面上点击任一来源 ID 打开来源详情页（含存档原文与引用片段高亮）；Excel 的「来源」表列出每个被引用来源的网址、发布日期与抓取时间。

## 4. 事实、推断与置信度

口径与对方材料《方法口径》表一致：

- **事实**：来源原文直接支持的值（接口返回值、原文明确陈述的数字与日期）。
- **推断**：分析判断，例如由试验推导的管线与阶段、评分、推荐逻辑、收购成本估算、资产权益中按完整列举得出的结论。推断必须带置信度：高 / 中高 / 中 / 低（「低」为本项目新增，用于弱证据推断，如收购成本区间）。
- **LLM 抽取**：属于事实，但额外记录原文片段与模型名；页面与 Excel 中标注「LLM」。
- **找不到来源**：字段留空，记入缺口清单 `data/processed/gaps.csv`（当前 174 条，Excel「缺口」表）。

## 5. 字段由谁产生

每条声明记录值的产生方式（`Claim.produced_by`），共三种。抽样核验的三层（[`verification.md`](verification.md) 第 1 节）就按它划分。

| 产生方式 | 含义 | 声明条数 | 占比 |
|---|---|---|---|
| `api`（结构化层） | 程序从官方接口取数，或由这些数据按固定规则计算（管线推导、自动初筛分、市值、资金可支撑月数） | 62,000 | 90.3% |
| `manual`（复核层） | 人工文件：对方材料导入、复核文件（AI 起草、用户签字）、排除名单、债务调整、治疗领域关键词表 | 6,366 | 9.3% |
| `llm`（LLM 层） | DeepSeek 抽取、千问盲抽核验，逐条接受后签字入库；每条附原文片段与模型名 | 323 | 0.5% |

**LLM 只写了下面 9 个字段**，全部来自 5 家深度研究公司（ARWR、CLDX、RGNX、VKTX、VSTM）的新闻稿与 10-K / 10-Q 正文：

| 内容 | 字段（声明条数） | 为什么用 LLM |
|---|---|---|
| 公司披露的未来事件 | 事件描述（24）、时间窗口起（22）、时间窗口止（22） | 「预计四季度公布数据」只出现在新闻稿与财报正文里 |
| 资产的作用机制 | 作用机制（18）、技术类型（15） | CT.gov 不登记作用机制 |
| 临床结果 | 终点（76）、结果（76）、对照组（34）、统计分析（36） | 新闻稿中的 topline 数据不在 CT.gov 已发布结果里 |

**其余字段都不由 LLM 产生：**

| 内容 | 字段 | 产生方式 |
|---|---|---|
| 试验 | 状态、阶段、入组人数、开始 / 完成日期、设计、适应症、干预措施 | `api`：ClinicalTrials.gov |
| 管线 | 适应症、研发阶段 | `api`：由 CT.gov 试验推导，FDA 说明书确定已上市 |
| 财务 | 现金及投资、债务、经营现金流、股本、股价、市值、资金可支撑月数 | `api`：SEC XBRL、Nasdaq；债务另有 `manual` 调整 |
| 获批产品 | 申请号、品牌名、活性成分、首次批准日期 | `api`：openFDA |
| 评分 | 自动初筛五维分、买方匹配分 | `api`：按 [`scoring-rules.md`](scoring-rules.md) 计算 |
| 买方 | 画像、偏好、财务、专利到期产品 | `manual`：对方材料 |
| 研究判断 | 推荐方向、推荐逻辑、资产权益、交易形式、复核后的分数与下一事件 | `manual`：复核文件 |
| 收购成本 | 估算区间 | `manual`：复核文件，方法见各公司研究说明 |
| 治疗领域 | 适应症所属领域 | `manual`：关键词表 |

条数按当前快照统计：`sqlite3 data/processed/intel.db "select produced_by, entity_type, field, count(*) from claim group by 1, 2, 3"`。

## 6. 归一化

不同来源对同一事物写法不同，配对、比较与计数前先统一。规则都在代码或 `data/manual/` 下可审阅的表格中。

| 对象 | 原始数据的问题 | 处理 | 代码 / 文件 |
|---|---|---|---|
| 公司 | 同一公司在 SEC、CT.gov、openFDA 中名称不同（openFDA 写作「ACADIA PHARMS」等缩写） | 先映射到 SEC CIK；名称转小写、去掉股份类别与 Inc、Corp 等后缀；补 openFDA 缩写规则 | `ingest/universe.py`、`ingest/pool.py`、`ingest/openfda.py`；修正后获批产品 51 → 105 |
| 试验归属 | 申办方写作子公司或曾用名 | 申办方别名表（20 条），每条注明依据 | `sponsor_aliases.csv` |
| 别家公司的药 | 试验中出现大型药企的研发代号（如 PF-、MK-、AZD），不是标的公司的资产 | 研发代号前缀表（22 条）识别所属公司，不计入标的管线 | `sponsor_code_prefixes.csv` |
| 药物（资产） | 同一药物在不同试验中带剂量、给药途径、括号说明，或用品牌名 | 去掉剂量、途径与括号后统一大写；合并 openFDA 品牌名；人工别名表 | `ingest/ctgov.py` 的 `normalize_intervention`、`program_aliases.csv` |
| 非资产干预 | 对照药、安慰剂、背景疗法被当成资产 | 通用疗法过滤，另加人工排除表 | `ingest/ctgov.py`、`intervention_excludes.csv` |
| 研发阶段 | CT.gov 以组合登记（如 `PHASE1, PHASE2`） | 统一为 9 个受控取值（临床前、1 期、1/2 期、2 期、2/3 期、3 期、已申报、已上市、未知）；已上市以 FDA 说明书适应症为准 | `enums.py` 的 `Stage`、`ingest/ctgov.py` |
| 治疗领域 | 适应症为自由文本 | 关键词表（251 条）归入 14 个治疗领域；固定抽样 50 条检验，漏判率 12%，已补关键词 | `ta_keywords.csv` |
| 买方偏好 | 对方材料以文字描述偏好 | 映射表（30 行）对应到治疗领域与理想阶段，用户签字 | `buyer_preference_map.csv` |
| 财务 | 各公司使用的 XBRL 标签不同；合计与分项同时申报，直接相加会重复 | 按标签优先级取值，只取美元；统一取最近一期资产负债表日；年初至今经营现金流按月数折算后计算资金可支撑月数 | `ingest/financials.py`（RLAY 现金少算约 8 亿美元即在此修正） |
| 事件时间 | 「Q4 2026」「second half of 2027」等写法 | 换算为时间窗口起止日期；无法换算的留空 | `extract/load.py` |
| 原文核对 | 引号、横线、空格、大小写与千分位写法不一 | 比对前统一为 NFKC、直引号、ASCII 横线、单空格、小写；数字去掉千分位与小数末尾的 0 | `docs/text.py` 的 `normalize`、`numbers` |
| 空值 | LLM 返回「none」「n/a」等占位词 | 视为空值，不建声明 | `extract/load.py` |

枚举字段（研发阶段、置信度、资产权益、技术类型等）只收受控取值，由写入检查（`db.py` 的 `before_flush`）强制执行。

## 7. 没有使用的来源

| 来源 | 原因 |
|---|---|
| 付费数据库（Evaluate、Citeline、Cortellis 等） | 题面要求不使用付费数据库账号 |
| 需要登录或有反爬保护的网站（部分公司投资者关系网站、期刊全文、部分行业网站） | 不绕过访问限制；改用 SEC 申报附件与 PubMed 官方接口 |
| 行业网站上的收购溢价统计 | 没有给出样本与口径；改为自建 SEC 原文样本 |
| Stooq、Yahoo 等行情 | Stooq 实测需浏览器验证；均为非官方 |

对方材料中的 43 条来源链接已逐条检查：26 条可访问，16 条站点拒绝脚本访问（可在浏览器打开），1 条（`PFE-3`）是对方本机文件路径，无法访问。
