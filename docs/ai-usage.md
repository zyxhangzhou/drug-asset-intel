# AI 使用说明

本文按题面第三部分的 5 个问题作答。每个数字都可以在 [`docs/ai-log.md`](ai-log.md)（逐次记录）、[`docs/verification.md`](verification.md)（抽样核验）与 `data/raw/llm/ledger.jsonl`（LLM 调用账本）中查到。

一句话概括：**AI 负责几乎全部的编码、数据抽取与研究草稿；系统用程序规则强制每个值有来源，用原文比对和双模型交叉核验拦截幻觉；人工签字是数据入库的闸门，抽样核验给出各层错误率。**

## 1. 使用了哪些 AI 工具

| 工具 | 用途 | 用量 |
|---|---|---|
| Claude Code（Claude Opus 5.5） | 主力：需求分析、方案与规格、全部代码与测试、数据管道、研究草稿、文档 | 整个项目（2026-10-28 至 11-03） |
| Claude Code 子代理 | 并行研究与独立核对：45 家公司复核草稿（每家一个子代理）、LLM 抽取结果初筛、收购溢价样本收集、抽样核验的两位独立核对员、界面设计评审 | 复核草稿 45 个，其余按任务 1–5 个 |
| Claude Code advisor（更强的审阅模型） | 关键方案决策前的审阅：接口选型、抽取设计、交付范围 | 关键决策前（如接口选型、抽取设计） |
| DeepSeek `deepseek-v4-pro`（官方 API） | 非结构化文档抽取（新闻稿、10-K / 10-Q、演示材料）：作用机制、临床结果、催化事件 | 113 次调用，3.74 元 |
| 通义千问 `qwen3.7-plus-2026-05-26`（阿里云百炼） | 对同一文档盲抽，与 DeepSeek 逐字段交叉核验 | 113 次调用，2.14 元 |
| WebSearch / WebFetch | 查找一手来源（公司公告、SEC 文件、FDA 页面）、核实价格表与接口文档 | 研究与设计阶段 |
| Playwright（无头 Chromium） | 前端走查截图，桌面与手机宽度检查版面 | 每轮界面修改后 |
| OpenSpec | 规格驱动开发：每个代码变更先写提案、规格、设计与任务，AI 按规格实现，完成后核对并归档 | 10 个已归档变更、16 份主规格 |

LLM 抽取合计 226 次调用、5.88 元（预算上限 DeepSeek 15 元、千问 5 元，超限自动停止）。DeepSeek 只在非高峰时段运行。

`openspec/`、`mydoc/plans/`（变更拆分计划 v1–v6 与状态日志）和 `.claude/`（助手的技能配置）保留在仓库中，是 AI 辅助开发流程的原始记录。

## 2. AI 参与了哪些环节

| 环节 | AI 做了什么 | 人做了什么 |
|---|---|---|
| 需求理解与方案 | 读题面与两份对方 Excel，指出材料细节（如 APGE 已被收购仍在指数中）；起草方案、变更拆分与评分细则 | 审阅并批准方案；逐条批准评分细则 |
| 对方材料导入 | 编写导入程序，按对方「方法口径」表逐列划分事实 / 推断，逐格保留来源 ID | — |
| 候选池排除 | 程序比对 + 检索，起草 16 行排除名单（已被收购、本身是大型药企、工具或诊断），每行附一手来源 | 逐行确认后签字 |
| 结构化数据 | 编写 CT.gov、SEC XBRL、openFDA、Nasdaq 抓取与取数规则；由试验推导管线 | 抽查 5 家公司的现金、债务、股本、市值与试验数 |
| 评分与匹配 | 实现五维评分与买方匹配；起草治疗领域关键词与买方偏好映射 | 确认映射；对 10 家公司做不看分数的独立分档，检验排序 |
| 45 家公司复核 | 子代理每家读 10-K / 10-Q / 8-K、FDA、论文，起草复核文件（推荐方向、临床、下一事件、资产权益、推荐逻辑），并登记所引文件为人工来源（项目人工来源共 181 条） | 审阅汇总并签字（`verified_by`）；对口径分歧做决定 |
| 文档抽取（5 家深度研究） | DeepSeek 抽取、千问盲抽；Claude 子代理逐条给出接受 / 拒绝建议 | 逐家决定并签字 |
| 收购成本 | 子代理从 SEC 原文收集 31 宗收购的溢价，计算 5 家公司的估算区间 | 确认方法与签字 |
| 应用 | 编写 API 与前端（8 个页面），按用户评审意见多轮改版 | 提出界面意见、验收 |
| Excel 与核验 | 编写导出与抽样程序；两个子代理独立核对抽样；主代理裁定 | 抽查 5 份复核文件、核对 Excel 两行；确认两处已签字数据的修正 |
| 文档 | 起草全部交付文档 | 通读、修改 |

## 3. 如何验证 AI 生成或提取的信息

**程序强制（每次构建都执行）**

- **溯源规则写在数据库层。** 写入时检查：每个业务字段必须有声明引用已登记的来源；推断必须带置信度；LLM 声明必须带原文片段与模型名；枚举字段只收受控取值。`intel check-provenance` 非零即构建失败。当前快照 0 个溯源缺口。
- **原文片段校验。** LLM 抽取的每个值附原文引用，入库前程序确认片段逐字出现在存档原文中，并确认值中的数字出现在片段里。
- **双模型交叉核验。** DeepSeek 与千问对同一文档独立抽取，逐字段配对；不一致的条目进入人工复核。
- **评分检验。** `intel check-scoring` 检查高分有事实支撑、前 10 名证据覆盖率、权重敏感性。
- **300 项自动化测试**，覆盖每份规格的场景。

**抽样核验（2026-11-01，固定种子，每层 30 条）**

| 层 | 核对方式 | 错误率 | 95% 上限 |
|---|---|---|---|
| 结构化（CT.gov、SEC、openFDA、股价） | 程序与缓存的原始接口响应比对 | 0/30 | 11.6% |
| 人工复核字段 | 两个独立子代理对照原文，分歧由主代理裁定 | 4/30 | 30.7% |
| LLM 抽取字段 | 同上 | 2/30 | 22.1% |

6 个错误中 4 个已修正（含 2 处经用户确认的已签字数据），2 个属于来源挂在同一节的另一份文件、取值正确，列为已知限制。详见 [`docs/verification.md`](verification.md)。

**人工核对**

- 用户抽查 5 家公司的结构化数据（VKTX、RLAY、MDGL、MRNA、IMVT）：全部一致。
- 用户按固定种子抽查 5 份复核文件（ALLO、ARWR、BBOT、IONS、VSTM），逐项打开来源：0 个错误。
- 用户核对 Excel 中 VKTX、RGNX 两行与页面一致。
- 用户对 10 家公司做不看分数的独立分档，与评分排序对比，据此修正了一处规则套用偏宽。

需要如实说明：45 份复核文件由 AI 起草，用户审阅后签字；抽样核验的复核层与 LLM 层由 AI 子代理核对。逐项对照原文的人工核对，是上面列出的抽查。

## 4. 如何降低幻觉、遗漏和来源错误

**幻觉**

- LLM 只做非结构化抽取；能从官方接口取的字段（试验状态、入组、完成时间、现金、债务、审批）一律走接口，不让模型生成。
- 原文片段必须逐字出现在存档原文中，数字必须出现在片段里，否则拒收。实测中拦下了模型把两句原文拼成一个不存在的片段、从上下文补写「week 52」等时间点。
- 两个不同厂商的模型盲抽后逐字段比对；两模型一致的条目也要人工复核（实测发现过两模型一致但都把已发生事件当作未来催化剂）。
- 推断与事实分开存放，推断必须带置信度；页面上推断用空心圆点标出。
- 找不到来源就留空并记入缺口清单（当前 174 条），不填估算值。

**遗漏**

- 管线由 CT.gov 全量试验推导，不依赖模型回忆；按申办方别名、研发代号前缀与 openFDA 品牌名合并同药多名。
- 每份复核文件有固定结构（临床、下一事件、资产权益、推荐逻辑），缺项构建失败；深度研究缺临床、下一事件或收购成本时构建失败。
- 发现一类遗漏后回头系统排查同类：例如 IONS 漏计可转换票据后，逐家核对了入选 30 家中所有 XBRL 无债务标签的公司。

**来源错误**

- 来源登记表记录网址、发布日期、抓取时间；文档原文存档并记 SHA-256。
- 只用快照日之前发布的文件；快照日之后的事件（如 NTLA 的贷款）不计入数值，写进研究说明。
- 核验时按来源 ID 打开原文核对，而不是只看值是否合理；抽样发现的来源挂错问题已修正代码。

**AI 自查发现并修正的典型缺陷**

| 发现 | 修正 |
|---|---|
| SEC 现金标签不全，RLAY 现金少算约 8 亿美元 | 补充标签清单，加测试防止合计与分项重复相加 |
| 部分公司封面页流通股停留在 2022 / 2024 年，市值失真 | 取较新的股数；仍过期的不算市值、记缺口 |
| openFDA 申请人名缩写未标准化，18 家公司的自家药被当成别家药 | 补缩写规则，获批产品 51 → 105 |
| 对照药、背景疗法被当成公司资产 | 管线推导加通用疗法过滤 |
| 缺催化事件的公司因「缺失按满分」排名靠前 | 无登记事件改记 0 分（有来源） |
| 特许权变现负债、可转换票据未计入债务（PTCT、RGNX、IONS） | 人工调整文件计入企业价值，用户签字 |
| 重新抽取把未签字条目追加进已签字文件，可能借旧签字入库 | 追加新条目时自动清空签字 |
| 抽样发现交易形式误用买方匹配的来源 | 改为引用资产权益来源 |

完整列表见 [`docs/ai-log.md`](ai-log.md) 各条的「发现的问题 / 修正」列。

## 5. 继续开发时，哪些可以自动化，哪些需要人工审核

| 可以自动化 | 理由 |
|---|---|
| 官方接口取数与定期刷新（CT.gov、SEC XBRL、openFDA、股价） | 结构化、可比对原始响应，抽样 0/30 错误 |
| 新申报文件的发现与存档（EDGAR 申报列表、8-K 新闻稿） | 规则明确，存档带哈希 |
| LLM 抽取 + 片段校验 + 双模型比对，以及两模型一致条目的预填 | 程序校验能拦下大部分幻觉；费用低（5 家约 6 元） |
| 溯源检查、评分检验、抽样核对表生成、Excel 导出 | 已是确定性程序 |
| 数据变化提醒（试验状态变更、读出日期临近、新增债务） | 可对比两次快照自动生成 |

| 需要人工审核 | 理由 |
|---|---|
| 复核文件签字：推荐方向、推荐逻辑、资产权益 | 涉及交易判断，AI 草稿复核层错误率 13%（95% 上限约 31%） |
| 两模型不一致或被程序拒收的抽取条目 | 正是模型最容易出错的地方 |
| 修改已签字的数据 | 程序会自动清空签字；修正须人确认 |
| 评分规则、权重、买方偏好映射的调整 | 决定排序，属于业务判断 |
| 收购成本等低置信度推断 | 依赖方法假设（溢价区间） |
| 定期抽样复查 | 每次重大更新后按层抽样，人工复核其中一部分，跟踪错误率 |
